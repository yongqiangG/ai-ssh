# SFTP 本地与远程统一路径导航

## 原始需求

> 核实当前sftp文件传输面板功能。远程文件无法切换到根目录或者其他目录，只能在当前的用户目录下切换，本地文件可以切换目录，但是按钮独立于面包屑之外，使用起来有点割裂。核实后grill me

## 背景

- 远程面板连接切换时把 `remoteCwd` 固定为 `~`；远程列表过滤了 `.` / `..`，且界面没有远程目录选择或路径输入入口，因此只能从用户目录向下浏览，无法从界面进入 SFTP 可见的 `/` 或直接跳转任意目录。
- 后端 `SftpSessionPort` 已支持 `~`、`~/子目录` 和绝对路径；JSch 每次操作新建 channel，不能把服务端 channel 当前目录当作前端路径输入的解析基准。
- 本地侧已有 Windows 面包屑和独立的系统目录选择按钮；按钮位于列表标题栏，与面包屑分离，盘符切换也没有被纳入路径导航。
- `DirListView` 同时服务本地和远程，SFTP 传输目标使用操作开始时的当前目录拼接；现有客户端测试 13 个文件、124 个用例全绿，但没有覆盖根目录、盘符切换、路径输入和导航竞态。

## 决议

1. **问题：远程浏览范围是什么？** 结论：允许浏览 SFTP 会话可见的 `/` 以及权限允许的任意目录；理由是后端已有绝对路径能力，限制来自前端入口缺失而非传输协议边界。
2. **问题：连接后从哪里开始？** 结论：首次连接默认从 `~` 开始；理由是保留熟悉且较窄的起点，避免每次连接加载根目录。
3. **问题：如何进入深层或无明显入口的目录？** 结论：提供面包屑逐级导航、上一级按钮和可编辑路径；理由是同时覆盖可发现性和快速跳转。
4. **问题：远程相对路径如何解释？** 结论：支持 `.`、`..` 和普通相对路径，并以当前远程面板目录为基准解析；理由是前端可在发请求前归一化，改动小且符合用户对相对路径的预期。
5. **问题：远程路径有哪些锚点语法？** 结论：支持 `~`、`~/目录` 和 `/绝对路径`，与相对路径并存；理由是保留现有接口语义并明确区分家目录、根目录和当前目录跳转。
6. **问题：本地与远程如何统一？** 结论：共用一套路径导航组件，差异由本地/远程适配器提供；理由是统一交互而不强行统一 Windows 与 Unix 路径语法。
7. **问题：本地如何切换磁盘？** 结论：盘符作为可操作的面包屑根节点，菜单只显示当前可读取的逻辑盘；理由是直接满足跨盘切换并避免把不可用盘伪装成可进入状态。
8. **问题：本地原生选择目录按钮是否保留？** 结论：移除原按钮；理由是盘符面包屑、层级面包屑和绝对路径输入已覆盖目录切换，避免两套重复入口。
9. **问题：本地路径输入范围是什么？** 结论：支持 Windows 盘符绝对路径和 UNC 路径，不支持本地相对路径；理由是没有原生选择器后仍保留任意目录能力，同时保持解析规则明确。
10. **问题：无效或无权限路径如何处理？** 结论：保持当前目录不变，保留输入并显示错误；理由是避免失败后静默跳转造成误操作。
11. **问题：目录状态如何记忆？** 结论：远程按连接在当前应用会话内记忆，首次连接和应用重启回到 `~`；本地目录独立于远程连接并跨服务器切换保持；理由是兼顾连续工作与不持久化过期或敏感远程路径。
12. **问题：导航与传输如何并存？** 结论：传输使用启动时捕获的完整路径，导航不改变正在进行的目标，也不强制跳回目标目录；理由是浏览位置不应破坏已发起的传输意图。
13. **问题：连续点击导致请求乱序怎么办？** 结论：最后一次导航请求优先，旧请求不得覆盖新目录；理由是路径、列表和面包屑必须保持同一状态。
14. **问题：远程根目录的含义是什么？** 结论：`/` 表示 SFTP 会话可见根，chroot 场景下不承诺服务器物理根；理由是这是客户端能够可靠保证且符合协议权限边界的定义。

## 影响范围

- 客户端：`sftpStore` 的路径模型、远程按连接状态、本地盘符发现、导航竞态和传输刷新；`DirListView` 或新的共享路径导航组件；SFTP 面板样式与交互测试。
- 服务端：原则上不改变接口；相对路径若在客户端归一化，现有 `/list`、上传和下载接口继续接收解析后的路径。
- 文档与验收：新增根目录、相对路径、盘符切换、UNC 路径、错误保持、状态记忆和竞态回归用例。
