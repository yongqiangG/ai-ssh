# SFTP 当前目录实时过滤

## 原始需求

> 当前在sftp文件传输的面板,我想要新增搜索过滤文件的功能,这个好实现吗
>
> 我想要按照当前目录搜索,然后效果是实时输入,实时匹配过滤,grill me

## 背景

- SFTP 工作区是本地与远程双面板，两侧共用 `DirListView`，当前目录条目均已完整加载到前端。
- 当前列表只支持浏览、拖拽与刷新，没有搜索状态；后端 SFTP 接口无须参与当前目录过滤。
- 面板是紧凑的桌面工作台，搜索不能破坏现有排序、拖拽和目录导航行为。

## 决议

1. **问题：搜索范围与对象是什么？结论：**各自过滤本地或远程面板当前目录内的文件和文件夹名称，不递归子目录；理由是当前目录条目已在前端，边界明确且无需新增远程遍历成本。
2. **问题：如何匹配？结论：**对去除首尾空格后的输入做忽略大小写的连续字面子串匹配，中间空格和特殊字符均按普通字符处理；理由是该规则直观、实时且不会引入正则或通配符歧义。
3. **问题：何时执行过滤？结论：**每次输入立即在内存中过滤，不防抖、不请求后端，并保持原有目录优先与名称排序；理由是单目录数据已经在内存中，直接派生结果最简单稳定。
4. **问题：双面板搜索状态如何隔离？结论：**本地与远程各有独立搜索框和组件内临时状态；理由是两侧经常需要使用不同关键词进行传输定位。
5. **问题：搜索状态何时重置？结论：**实际切换目录时清空，刷新同一路径时保留，离开并重新进入 SFTP 视图时清空；理由是搜索只属于当前路径和当前视图会话，刷新不改变其作用域。
6. **问题：如何快速清空？结论：**有输入时提供清除图标，输入框聚焦时按 `Esc` 也可清空；理由是实时过滤需要低成本恢复完整列表。
7. **问题：空态、加载与错误如何呈现？结论：**无匹配时显示包含搜索词的专用提示，加载期间保留并禁用搜索框，错误时优先显示真实错误；理由是必须区分空目录、无匹配和读取失败三种状态。
8. **问题：搜索控件放在哪里？结论：**每侧搜索框放在面包屑下方、文件列表上方；理由是这里最清楚地表达搜索范围属于当前路径，并避免挤压标题操作区。
9. **问题：首版是否需要快捷键和匹配计数？结论：**不提供聚焦快捷键和结果计数；理由是双面板尚无活跃侧语义，且紧凑界面中的可见结果已经足够反馈。

## 影响范围

- `ssh-client/src/components/DirListView.tsx`：搜索状态、过滤派生、清空和空态行为。
- `ssh-client/src/components/DirListView.module.css`：紧凑搜索栏样式。
- `ssh-client/src/components/Icon.tsx`：搜索图标。
- `ssh-client/src/components/DirListView.test.tsx`：过滤与状态生命周期回归测试。
- 不修改 SFTP API、服务端实现、store 数据结构和传输逻辑。
