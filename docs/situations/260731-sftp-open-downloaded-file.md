# SFTP 下载完成后打开本地文件

## 原始需求

> 当前的sftp文件传输面板中,传输文件成功了下方会有进度条,现在想要在进度条旁边新增一个打开按钮,方便从远程拉日志文件可以直接点击打开文件,而不需要再去本地找到文件打开. grill me

## 背景

- SFTP 下载由桌面端直接写入用户选定的本地目录，但传输项目前只保存文件名，不保存完整目标路径。
- 成功的上传和下载记录当前都会在 1.8 秒后自动移除，无法承载后续打开操作。
- 客户端已经集成并授权 Tauri opener，可调用 Windows 默认关联程序打开本地文件。
- 远程下载内容不一定可信，直接打开可执行文件或脚本可能执行代码。

## 决议

1. **问题：哪些传输项提供打开入口？结论：**仅下载成功项显示带图标和文字的“打开”按钮；理由是上传项对应远程目标，本机没有可直接打开的新文件。
2. **问题：下载成功项何时消失？结论：**打开前一直保留至用户手动关闭，系统成功受理打开后按钮立即禁用并显示“已打开”，再延迟 1.8 秒移除；理由是原有 1.8 秒自动清理不足以完成点击，但打开后的延迟反馈可延续现有节奏并防止重复启动。
3. **问题：如何打开文件？结论：**调用 Windows 默认关联程序，不新增应用内预览器或“打开所在文件夹”；理由是目标是快速查看日志，系统关联程序覆盖面更广且实现边界最小。
4. **问题：打开失败如何处理？结论：**保留原“打开”按钮并展示包含上下文的错误，不增加独立“重试”状态；理由是下载已经完成，再次点击就是普通打开操作，无需额外状态机。
5. **问题：如何处理危险文件？结论：**扩展名为 `.exe`、`.com`、`.msi`、`.bat`、`.cmd`、`.ps1`、`.vbs`、`.vbe`、`.js`、`.jse`、`.wsf`、`.wsh`、`.scr`、`.hta`、`.lnk`、`.reg`、`.jar`（忽略大小写）时，每次打开前弹出风险确认，不提供永久放行；理由是远程文件可能不可信，而逐次确认成本只落在低频危险操作上。
6. **问题：取消风险确认后如何处理？结论：**不调用系统打开能力，不改变传输项状态，记录继续保留；理由是取消不是错误，用户仍可关闭记录或再次发起操作。

## 影响范围

- `ssh-client/src/stores/sftpStore.ts`：保存下载目标路径、打开状态、错误和延迟清理行为。
- `ssh-client/src/views/SftpPanel.tsx`：复用现有应用内确认框完成危险文件确认。
- `ssh-client/src/components/TransferTrack.tsx` 与样式：下载成功项的打开按钮、已打开状态和错误反馈。
- `ssh-client/src/components/Icon.tsx`：文件打开图标。
- `ssh-client/src-tauri/capabilities/default.json`：授权 opener 打开本地路径。
- 新增对应 store 与组件测试；不修改 SFTP 服务端和下载协议。
